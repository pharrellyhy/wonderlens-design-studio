# UX Polish: Back Button, Persistent Polling, Expandable Rubrics, SVG Icons

## Context

Phase 1 ships and works end-to-end, but the user surfaced four UX gaps during real use:

1. There is no way to leave the gallery and start over with a different YAML — once you upload, you're stuck with that entity unless you manually edit the URL.
2. Clicking a variant card while other variants are still generating navigates to the editor, which unmounts the gallery and silently kills the polling interval. New variants finishing in the background never reach the store, so when the user returns to the gallery, they see only what was generated up to the click.
3. The 9-dimension scorecard shows PASS/FAIL chips with no way to see *why* a dimension failed. The rubric data already includes per-dimension issue descriptions, but they're invisible.
4. The whole UI is emoji-driven. Emojis render inconsistently across OSes, can't be color-themed, and look like a stub. The user wants flat modern SVG.

## Plan

### 1. Back button + state reset

Add an `ArrowLeft` button to the gallery header pointing back to `/`. On click:

- `router.push("/")`
- Reset store fields tied to the current upload session: `parsedEntity`, `variants`, `activeDesign`, `activeDesignId`, `rubricScores`, `generationJobId`
- Stop any active poller (see #2)

Add a `resetSession()` action to the Zustand store that clears all of those at once. The persisted LLM config (`llmProvider`, `apiKeys`) is *not* touched.

### 2. Persistent polling across navigations

The polling interval currently lives inside `gallery/[entityId]/page.tsx` as `useRef + setInterval`, with cleanup on unmount. That's the source of the bug.

Extract the polling into a module-level singleton in `src/lib/generation-poller.ts`:

- `startPolling(jobId, callbacks)` — sets up an interval that polls `/api/generate/[jobId]/status` every 3s. Survives component unmount.
- `stopPolling()` — clears the interval.
- The poller writes results directly into the Zustand store via callbacks (`addVariant`, `setGenerationError`, etc.) so any mounted component sees updates.
- The poller stops itself automatically when the job becomes terminal (complete/failed).

Gallery wiring:

- On Generate click → call `startPolling(newJobId, ...)`. Save jobId in the store via `setGenerationJobId`.
- On gallery mount → if `generationJobId` is set in the store and the poller isn't already running for it, resume polling.
- On variant card click → navigate, but **don't** stop the poller.
- On back button → `stopPolling()` + `resetSession()`.

This way, the user can click a variant, work in the editor, return to the gallery, and find the new variants already there — or see them appear live if they return before generation finishes.

### 3. Expandable rubric dimensions

`src/components/editor/ScorecardPanel.tsx` currently renders each dimension as a chip. Refactor each row into a button that:

- Shows the dimension code (D1-D9), short label, PASS/FAIL chip, and a chevron.
- On click, expands inline to show:
  - The full dimension description (static text per D1-D9, defined in a small lookup table)
  - Any failing-issue text from `rubricIssues` for that dimension (we already have this from `/api/evaluate`)
- Multiple rows can be expanded independently. Use local component state (`Set<string>`) — no need to lift this into the store.

We need to plumb `issues` into the scorecard. The editor page already calls evaluate and stores the issues — currently they're discarded. Add `rubricIssues` to the store, populate it on activate-design and on re-run-rubric, and pass it into `ScorecardPanel`.

### 4. Emojis → flat SVG icons + polish

Add `lucide-react` to dependencies. It's the de-facto Tailwind-friendly flat icon set, MIT-licensed, tree-shakeable.

Emoji → icon mapping (rough):

| Location | Emoji | Lucide icon |
|---|---|---|
| Upload drop zone | 📁 | `Upload` (or `FilePlus`) |
| Gallery "YAML parsed" badge | ✓ | `CheckCircle2` |
| Gallery Regenerate All button | ⟳ | `RefreshCcw` |
| Gallery back button (new) | — | `ArrowLeft` |
| Editor scorecard header | 📊 | `BarChart3` (or `Gauge`) |
| Editor Re-run Rubric | 🔄 | `RotateCw` |
| Editor AI Comment Box | 💬 | `MessageSquare` |
| Editor Export Design | 📥 | `Download` |
| Editor Back to Gallery | ← | `ArrowLeft` |
| Editor field "Ask AI" | ✨ | `Sparkles` |
| Editor field "comment" | 💬 | `MessageCircle` |
| Editor field "regen" | ✨ | `Wand2` |
| Nav tree icons (📋 🎯 🎨 🌉 📖 🔄 🎉 👋) | various | omit — use the section title alone, or pick neutral icons (`Info`, `Target`, `Palette`, `ArrowRight`, `BookOpen`, `RefreshCw`, `PartyPopper`, `Hand`) |
| Variant card metaphor 🎭 / badge 🏅 / escalation 📈 | various | `Drama`, `Award`, `TrendingUp` |

Polish (light, consistent):

- All icons rendered at 16px (`w-4 h-4`) for inline button text, 20px (`w-5 h-5`) for headings.
- Consistent icon-text gap (`gap-2`).
- Use `text-` colors so icons inherit the parent text color and stay theme-consistent.
- Hover state on the back button.
- Variant card: tighten the pass/fail summary chip styling.

## Verification

1. `npm run build` + `npm run lint` clean.
2. Browser walkthrough (Goldfish + Apples):
   - Upload, generate variants, click into one before all are done. Verify other variants still appear in the store when navigating back to the gallery (or appear live if you return before completion).
   - Click back button on gallery → lands on upload page with empty drop zone, no entity loaded.

## Out of scope

- Multi-user concurrent jobs (the in-memory `jobs` Map is still single-process).
- Server-side cancel of in-flight generation.
- Rubric dimension descriptions becoming editable / configurable.
- Icon library replacement beyond `lucide-react`.
