The WonderLens
Pipeline.

From a single entity name to a running game with sound, animation, and live photo capture — an intern's guided tour through eight stations and two hand-carried seams.

Stations
Eight, in three bands
Seams
Two, hand-carried
Walkthrough
~Half a day
Audience
New interns

Reading time
~18 minutes

Doing time
~4 hours

WonderLens is three things pretending to be one. Upstream, a small set of Python scripts produces structured data — a list of entities, their IB theme assignments, age-tier scaffolding. In the middle, the design studio runs an LLM pipeline that turns that data into dialogue designs scored against a ten-dimension rubric. Downstream, a FastAPI backend and a React frontend take recipes and actually play them as games, with audio cues, animated widgets, and a photo-capture loop.

Today the three bands work. But the connections between them are not yet machined. Between upstream data and the studio, one hand-written context file stands in for what should be a structured read of the generated YAMLs. Between the studio's prose export and the runtime's recipe format, a one-shot LLM call does the conversion work — unreliable, opaque, and the single biggest candidate for future automation. Those two connections are what this field guide calls seams, and they are the most important thing for a new intern to understand.

Convert Game

Band III · Runtime
File
refs/scripts/convert_game.py
Input
spec.md from the studio.
Process
Calls Gemini with a structured-output schema to extract widget, animation, sfx_cue, tone markers, and the rest of the recipe fields from prose.
Produces
refs/backend/games/*.md — markdown with YAML frontmatter plus a narrative body.
Takeaway
This is the most fragile step in the whole pipeline. It's an LLM call, not a deterministic transform. A good convert step would have no LLM in it at all.

§ 02

The two seams

Where data is hand-carried
Seam A · Between Band I & Band II

Scripts produce YAML. The studio ignores it.

scripts/*.yaml → src/lib/prompts/generate.ts

Stations 2 and 3 produce structured entity_ib_map.yaml and tier_guidance.yaml. But generate.ts loads data/entity_guidance.md — a hand-written markdown file — as context instead. So every generation run asks the LLM to re-invent the IB theme and tier scaffolding from scratch.

The fix is small in code but large in consequence: pass the YAML contents into the prompt as structured context, cite the IB theme deterministically, and let the rubric check that the output matches.

  • Studio cannot cite a deterministic ib_theme or ib_key_concept
  • Tier scaffolding drifts run-to-run — same entity, different tier treatment
  • concepts_earned can't be pre-computed; runtime synthesis relies on LLM guesswork
  • Two evaluation scripts (llm_age_tier_adherence_eval.py, llm_conversation_benchmark.py) exist but aren't part of the rubric pipeline
Seam B · Between Band II & Band III

Studio exports prose. Runtime needs widgets.

src/lib/markdown-export.ts → refs/scripts/convert_game.py

The studio emits a beautifully human-readable spec.md with prose screen descriptions like "golden glow, sparkles, dotted line." The runtime's ScreenFrame schema requires structured fields — widget, widget_params, animation, trigger, sfx_cue, sfx_label. A Gemini call bridges the two.

This is the biggest single candidate for automation. Extend the GameDesign schema to carry runtime fields, export YAML frontmatter directly, and convert_game.py disappears.

  • No YAML frontmatter on export — activity_type, metadata missing
  • No tone markers — [warm], [excited] can't survive the round trip
  • No structured screen frames — prose only, so widgets must be guessed
  • No SFX / BGM / animation IDs anywhere in the schema
  • No cat5 collection_catalog, collection_count, photo_features
  • No celebration_frame
§ 03

The walkthrough

Six stations · ~half day

Do these in order. Each exercise consumes the previous one's output. By the end of Station VI you will have followed a single SFX cue from a string ID in a YAML file all the way to the sound playing in a running game.

Lab · 01

Entities, themes, tiers

Upstream data is deterministic and structured.
Open
scripts/entity_list_generator.py, scripts/ib_theme_batch_generator.py, scripts/exploration_tier_generator.py
Run
The three scripts in sequence.
Inspect
Pick three entities from entities.csv. Find them in both generated YAMLs. Do the theme and tier assignments make sense?
Ask yourself
If the studio could read these files, which fields would it stop guessing?
Lab · 02

Generate a design

Studio produces dialogue — not assets.
Open
src/lib/design-schema.ts, src/lib/prompts/generate.ts
Run
npm run dev, upload an entity YAML, click Generate.
Inspect
Open the resulting JSON under data/runs/. Export the spec. Count the fields that have nothing to do with audio, animation, or widgets.
Ask yourself
If you handed this spec to the frontend, what would be missing?
Lab · 03

Read the runtime schema

The runtime is strict. Match or die.
Open side by side
refs/backend/schemas/recipe.py, refs/backend/schemas/visual_composition.py, src/lib/design-schema.ts
Exercise
List every field the runtime requires that the studio doesn't produce. Cross-reference with the gap table in §04.
Ask yourself
Which of these could be generated by the LLM if you added them to the prompt schema? Which need a separate deterministic step?
Lab · 04

Inspect a finished game

This is the target format.
Open
refs/backend/games/polka_dot_patrol.md
Exercise
Diff the frontmatter against the spec.md from Lab 02. Highlight every field that the studio would need to learn to emit.
Ask yourself
How much of the frontmatter could be filled in mechanically from Band I data?
Lab · 05

Run the manual bridge

Seam B up close.
Open
refs/scripts/convert_game.py
Exercise
Read the Gemini prompt the script uses. Find the parts where it guesses widget types, animations, and SFX cues from prose. Which are brittle?
Ask yourself
If the studio emitted these IDs directly, what part of this script survives?
Lab · 06

Play it

Follow one sound to its source.
Open
refs/backend/server.py, refs/frontend/
Run
Start the backend, start the frontend, load polka_dot_patrol.
Exercise
Pick one SFX cue you hear. Trace it from the running game → recipe JSON on the wire → sfx_cue ID in the game MD frontmatter → audio file on disk.
Ask yourself
You just walked the full chain of custody. Where does it break down today?
§ 04

Field gaps

Runtime schema vs. studio schema
Table 01 · verified against refs/backend/schemas/recipe.py & visual_composition.py
Runtime field Studio equivalent Status Consequence
activity_type — missing No frontmatter on export. Runtime can't auto-load.
metadata.ib_theme / ib_key_concept / concepts_earned / round_count basicInfo.ibTheme (one string) partial Theme is a single blob; key concept and earned concepts not decomposed.
voice_script.hook_tone / closing_tone / tone_marker — missing Tone markers like [warm] can't survive the round trip.
screen_frames[].widget / widget_params / animation / trigger / sfx_cue / sfx_label Step.screenDescription (prose) missing Prose, not structured. Gemini has to guess. Seam B's core.
celebration_frame — missing No celebration frame can be emitted.
collection_catalog (correct + distractors) creativeVariables.collectionCriterion partial Criterion name exists; catalog of valid and invalid items does not. Cat5 blocker.
photo_features — missing Vision validation of photos has no hints to match against.
voice_script body (hook, rounds, synthesis, closing) Step dialogue blocks structurally ok Phase names differ but content maps cleanly. Renaming is cheap.
rubric / quality score 10D rubric on GameDesign studio side only Runtime doesn't consume this, but it's useful upstream for variant selection.
